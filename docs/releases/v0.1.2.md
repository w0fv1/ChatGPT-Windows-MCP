## v0.1.2 — Runtime health and process-safety fixes

### 修复内容

- 子进程退出后进入故障状态，不再继续显示虚假的“已连接”。
- 使用带运行代次的健康快照，隔离旧进程与旧探测结果；启动、停止与诊断串行化。
- 每 5 秒被动检查本地端口与回环 `/readyz`；旧版没有健康接口时明确显示“未验证”。
- 固定 tunnel-client 版本使用独立安装目录和 SHA-256 安装记录；不再误用已有的其他版本 EXE，也不再在 latest 查询失败后静默降级。
- 命令取消时请求清理自己启动的进程树；移除按端口猜测 PID 并终止进程的逻辑。
- 增加 30 个回归用例，并在 Windows 构建和发布前执行；日志文件写入失败不再直接破坏运行状态，界面日志缓冲设有上限。

### 下载与升级

下载附件 `ChatGPT-Windows-MCP-win-x64.zip`，而不是 GitHub 自动生成的 Source code。先停止旧启动器并保留旧版，在新目录解压测试。可在本机复制自己的 `config.json`，不要将其中的 Runtime API Key 上传到 GitHub。用 `SHA256SUMS.txt` 核对下载包；包内 `SOURCE_COMMIT.txt` 标明构建源提交。

### 验证范围与已知限制

发布流程要求 Windows Release 编译、30 个回归用例、便携 EXE 打包及上传附件回读校验全部成功。CI 不使用用户 API Key，也不执行真实桌面工具操作。

**本版没有声称已经验证或修复真实 ChatGPT 双会话的 `Session terminated` 根因。** 本地端口和 `/readyz` 通过不等于 ChatGPT 会话或写入工具可用。仍需真实环境的 A → B → A 调用测试。ChatGPT 的只读筛选、工作区动作权限及工具清单不由该补丁修改。

不会自动重放点击、输入或 PowerShell，不会自动创建或删除 MCP 会话。Runtime API Key 的本地明文便携存储保持原行为。安装记录的 SHA-256 是缓存完整性检查，不是发布者签名或对二进制自报版本的认证。

`latest` 仍采用已有缓存优先策略，不会每次启动自动升级；旧根目录缓存会明确标记为版本未核对。需要固定版本时，在停止服务后设置 `TunnelClientVersion`。
